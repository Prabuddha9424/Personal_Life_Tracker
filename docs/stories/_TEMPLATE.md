## User story

> **As** a <role>, **I want** <a goal>, **so that** <the benefit>.

Write it from the point of view of the person who benefits. Use "a developer" or "the operator" only when the value is really theirs. Keep it independent, negotiable, valuable, estimable, small and testable (INVEST).

## Acceptance criteria

1. **Given** <a starting situation>, **when** <something happens>, **then** <the observable result>.
2. ...

Each criterion describes behaviour someone can check, in words a non-programmer understands. Include the unhappy paths (invalid input, another user, a failure), not only the happy one.
